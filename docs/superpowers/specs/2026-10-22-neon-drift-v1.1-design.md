# Neon Drift v1.1 — approved challenge and feel upgrade

Abel approved the offered v1.1 package with “boleh”: Normal/Hard, varied small-fast/large-slow vehicles, near-miss combo, obvious nitro feedback, richer car/rain/city/boost visuals and engine/boost/near-miss sound with mute. Existing v1.0 source/tag and live build remain untouched while working in feat/neon-drift-v1.1. Parent owns independent acceptance/release; single implementation writer. No unrelated provider/config/credential/service changes.

## Domain and fairness
- Remain deterministic pure Engine.create({seed,mode='normal'}), immutable snapshot and CONFIG; invalid mode throws before mutation. start/replay retain selected mode; mode changes only on a fresh run. No mutable UI game-state hook.
- Normal start36/cruise46/maxCruise58/difficultyRate.12, Hard start42/cruise52/maxCruise66/difficultyRate.20 (m/s and active seconds); boost84/brake22, acceleration24/deceleration48, steerRate1.6 unchanged. Expose frozen MODE_CONFIG for exact mode parameters.
- Spacing Normal begins140 and approaches125 by120 active seconds; Hard begins125 and approaches108 by90 active seconds. Never generate a three-lane wall; preserve lateral offset phases from v1.0 so no permanently safe inter-lane parking.
- Frozen VEHICLES: compact width.28 length3.8 desired speed22; sedan width.34 length4.4 speed20; van width.46 length6 speed16. Each wave has one type/shared actual speed and 1–2 occupied lanes; at least one integer lane center clear. Seeded type variety must occur in both modes. Snapshot cars include type,width,length,speed,wave/id/x/z/color; renderer uses actual widths and clear type silhouettes, not uniform hidden hitboxes.
- Actual waves must never bunch into impossible walls: maintain a conservative per-run gap at least125 Normal /108 Hard between successive wave centers even with differing traffic speeds. Trailing wave traffic may slow behind leading traffic; enforce this during integration (not teleports). Document the rule and test mixed-wave approach. Spawn lookahead310, bounded population10.
- Generalize swept contact half-width/length per vehicle (optional radii on pure helper, old defaults remain). Near-pass band ends at contactHalfWidth+.16. Earliest collision truncates every resource/time/position, no rewards in colliding substep.
- Worst speed differential68, full lateral traversal1.25s, max contactHalfLength5.2: safe wave center gap must exceed95.4m. Hard minimum108 satisfies this including both contact zones. Prove successful sustained traversal with a deterministic pure-domain driver across mixed types/offset phases; not merely that center runs crash. Preserve stationary-corridor regressions both modes.

## Nitro and combo
- Initial55, drain26/s, near-pass base recharge16 capped100, no passive refill. Each vehicle rewards once only after it passes the full actual-length contact zone.
- First near pass combo1/multiplier1; subsequent passes within8 active seconds of previous pass increment count, multiplier=min(4,count). Expiry resets to0/1. Pause/hidden time does not expire it. Replay resets everything.
- Score=floor(distance*2)+nearMissBonus; nearMissBonus accumulates150*multiplier per rewarded pass. Nitro reward remains16 regardless of combo. Never retroactively multiply distance/previous rewards.
- Snapshot: combo,multiplier,comboRemaining,nearMissBonus,bestCombo,lastNearMiss (detached immutable event {id,elapsed,nitroAdded,bonus,combo,multiplier}); lastNearMiss ID strictly increases per run. HUD event appears once per ID, displays actual capped nitro added, and expires by active simulation time. Readable `NEAR MISS · +16 NITRO` when full16 awarded; meter pulse, combo text/time indicator, explicit menu/tutorial explaining pass close then fully clear. No color-only meaning or excessive live-region announcements each frame.

## Input, records and audio
- Preserve original keys/touch simultaneous holds, cancellation, blur/pagehide/hidden auto-pause, explicit resume, single active rAF and idle/result zero loop. Enable/render before focusing pause.
- Native mode selector ready/results only; never silently change difficulty mid-run. Display selected mode HUD/results. Existing Normal record key/schema retained; Hard uses separate key (suffix `.hard`), with whitelisted bounded validation and truthful denied/quota outcomes. No erasure of existing records. Records.open(storage,{mode='normal'}) keeps backward-compatible default.
- Separate audio.js lazily creates/resumes WebAudio from a real user gesture; sound opt-in native checkbox/toggle defaults muted, with explicit current label/status. Synthesized engine pitch follows speed; boost voice/noise and one-shot near-pass cue. No external sound download/dependency/network, no mic permission.
- Audio never blocks gameplay. Unsupported/rejected creation/resume is caught, user is shown unavailable rather than false sound-on. Mute, pause, blur, hidden and results silence sustained voices immediately. At most one context/engine voice set per controller lifetime; replay does not leak oscillators/timers, no asynchronous resume race revives sound after pause/mute.
- Follow MDN WebAudio best practices and AudioContext.resume docs fetched by parent: user gesture creation/resume, own controls, handle promise rejection. Real OfflineAudioContext waveform/RMS tests plus real browser context/lifecycle instrumentation; no claim of human auditory/device certification.

## Visual design
- Keep responsive dark teal/amber neon aesthetic but materially upgrade silhouette/material detail, rear/brake lights and reflections. Small compact vs tall/wide van must look distinct and match simulation dimensions.
- Visible bounded body roll/steering response, tire trails, wheel spray; layered skyline districts/signs/parallax; stronger boost exhaust/speed feel. World road/vehicle positions remain matched to hitboxes, not decorative steering offsets that lie about collisions.
- Reduced motion/decorations toggle suppresses rain/spray/trails/camera shake/speed streaks/body roll; essential road/traffic remains. No strobe; effects bounded for mobile, no per-frame randomness changing domain. HUD stays readable over effects and all controls fit320xsmall,390x844,768,1366x768,1440; DPR cap2.
