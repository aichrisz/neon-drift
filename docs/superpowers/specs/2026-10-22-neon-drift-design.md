# Neon Drift — approved local v1.0.0 design

## Approval and scope
Abel asked for Neon Drift and answered “Yap” to the presented pseudo-3D rear-camera design, endless traffic, limited nitro replenished by near misses, keyboard/touch, pause/results/retry, local records and standalone offline HTML, using exact model `gpt-6-astra`. This document formalizes those defaults, not a new product interview. Local build only: no public repo/deploy, accounts, paid assets, services or global/provider changes. Potion/Ranoa publication permissions do not carry over.

## Experience
An original fast arcade driving game: cyan/acid-lime/amber signage, midnight asphalt, animated rainy skyline and reflections, a visible rear-view player car and approaching traffic. A road converges at a real horizon (pseudo-3D perspective scaling); not a top-down rectangle game or marketing page. Three continuous road lanes, smooth lateral steering within lane boundaries, tasteful car lean/skid/reflection effects. Road bends may be cosmetic, never invisible hitbox changes. No realistic tire/vehicle simulation. Indonesian instructions and truthful HUD. Zero runtime dependencies, external assets/fonts/trackers/backend/audio requirements.

Ready screen: objective, controls, collision rule, record, optional decoration toggle, usable Start only after successful initialization, meaningful noscript. Running: distance, speed, score, nitro gauge, near misses, pause and always accessible controls. First traffic far enough away to learn steering. Collision ends run once; final card shows real distance, score, near misses and record/save outcome; replay clears active stats. Endless difficulty rises gradually with active time and caps, never an unbeatable timer or level.

## Simulation and fairness
- DOM-free seeded deterministic engine with explicit time seconds; states ready/running/paused/results; all other UI/render/storage outside.
- Steering held by A/D or Left/Right and pointer-held touch buttons; left+right neutral. Native controls release on pointerup/cancel/lostcapture, keyboard keyup, blur, hidden, pause, results and replay. Steering is smooth and bounded; do not teleport on resize.
- Brake held by Down/S; nitro held by Space/Up/W or labeled touch button. Auto acceleration otherwise. Nitro pool starts partially filled, is clamped 0..100, consumes real active time only when boosting and restores only for qualifying near misses; cannot boost with an empty pool. Brake has priority over nitro so resources do not drain while braking. Release at least restores normal speed target; finite positive speed with a capped difficulty envelope.
- Lane centers -1/0/1, lateral world x bounded [-1,1]. Cars have explicit world widths and longitudinal collision lengths. Define and document numeric speeds, collision/near-miss thresholds, fixed step size, score formula and difficulty caps as a public immutable CONFIG, not magic renderer numbers.
- Traffic drives forward slower than the player. Seeded waves of at most two cars always leave at least one open lane. Spawn lookahead and longitudinal spacing must exceed the maximum time needed to traverse two lanes at the minimum steering rate, accounting for maximum nitro relative speed and collision length. Document and test the inequality. No last-second spawning beside player, hidden faster traffic or three-lane walls. Bound active traffic count and delete passed cars.
- Collision checks must be swept across both longitudinal and lateral movement or use sufficiently bounded fixed substeps plus a swept longitudinal intersection; no tunneling at high speed or large valid deltas. Crash must stop the integration at contact: no post-crash distance/reward. Pause, ready and results never progress.
- Near miss is awarded only when a car actually passes behind the player without collision, at a documented narrow lateral clearance outside collision width, and never twice per vehicle. A far pass gives no bonus; a crash gives none. Bonus score and nitro recharge are explicit, bounded integer events. No held-button points.
- Score = documented distance component + documented near-miss bonus; distance/elapsed finite nonnegative, integer HUD score, exact once-only finish/record handling. Seed reproducibility and detached snapshots/config are required. Invalid/nonfinite/negative input/delta is rejected without poisoning state. Bound expensive input delta to an explicit maximum or integrate bounded work; document semantics. Controller caps browser frame delta and pauses lifecycle loss rather than catching up hidden time.

## Stable interface
`Neon.Engine.create({seed})` produces `start()`, `setInput({left,right,brake,nitro})`, `step(seconds)`, `pause()`, `resume()`, `snapshot()`. Replaying `start()` must reset run and input while preserving caller-owned stored record. Snapshot includes phase, elapsed, distance, speed, score, nitro, nearMisses, playerX, traffic (id,x,z,passed or derived), crash info and any renderer-only camera values needed. Expose same domain engine through CommonJS and browser namespace; no production mutable live-game test hooks. Test seams belong in pure functions/config/seed, not query flags that disable collisions. Controller uses one rAF chain while running, no persistent loop in ready/paused/results/hidden. Renderer can be called once to draw static menu scene.

## Architecture / controls / visuals
`engine.js` domain; `renderer.js` Canvas road/cars/sky/rain; `app.js` input/lifecycle/safe storage/DOM; `index.html` semantic UI; `styles.css` responsive layout; at most two local SVG marks if useful. Canvas world aspect remains consistent across desktop/mobile with DPR capped2; actual CSS size/bitmap transform/pointer targets verified. Controls min44px, clear focus, properly labeled HUD/gauge/buttons/dialogs, selected pressed states where appropriate. Do not move/replace focused native controls each frame. No keyboard capture when not running except explicit resume/start native interaction. P/Esc pauses from focused controls; Space must not scroll while controlling nitro. Explicit resume after blur/hidden; clear input on all lifecycle transitions. Reduced-motion/decoration setting reduces rain/shake/speed streaks only; necessary world motion remains. Avoid fullscreen flash/strobe; no forced sound.

At320×844,390×844,768×1024,1366×768,1440×900: no horizontal overflow, no clipped modal; entire driving view plus essential controls simultaneously usable after scrolling game section into view, not merely full-page screenshot. Touch simultaneous steering+nitro works and releases cleanly after cancellation. Resize mid-run preserves domain state. Keyboard-only start→steer→brake/nitro→pause/resume→crash→retry usable. Text fallback describes Canvas controls, timing/visual limitations honestly; automated axe does not prove nonvisual driving equivalence.

## Storage
Key `neon-drift.records.v1`; JSON version1 with whitelisted integer bestScore (0..1e9), bestDistance (0..1e9), bestNearMisses (0..1e7), runs (0..1e6). Max raw1024 bytes. Invalid/oversize/wrong-type/prototype-like data defaults/sanitizes without HTML interpolation. Store completed runs only exactly once; no active restoration. Denied read or write leaves game playable with session record and accurate visible result-dialog save status. Read success does not imply write success. Replays and reload do not invent completed runs; profile is detached and origin-specific.
